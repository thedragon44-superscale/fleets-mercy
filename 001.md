# Migration Guide: Moving from Clean Binary Baseline (`511994b`) to the "Tangled/Extended" Feature State

If you want to move from your current clean, baseline repository state (`511994b`) back to the extended feature state (where JSON hybrid inputs, FlatBuffers code-gen folders, and live inspector tabs were introduced), here is the exact architectural roadmap and step-by-step procedure of what was added.

---

## 1. Understanding Where the "Generated" Folder Came From
The `generated/` folders do not exist in the clean base repository because they are **compiled output artifacts** produced by the FlatBuffers compiler (`flatc`). 
* **The Schema Source:** Defined in `schemas/game_state.fbs`.
* **Frontend Output:** Compiled into `src/generated/` (e.g., `src/generated/space-tactics/...`) to provide TypeScript classes for unpacking binary frames.
* **Backend Output:** Compiled into `backend/internal/generated/SpaceTactics/` to provide Go binary builder structs.

To recreate them when moving forward, you run the `flatc` compiler against your `.fbs` schema files.

---

## 2. Step-by-Step Feature Integration Roadmap

To re-introduce the features that created the tangled state without breaking your core pipeline, follow these integration phases:

### Step 1: Install Required Packages (If not already present)
Ensure your frontend and backend have the necessary transport libraries:
* **Frontend (`package.json`):** Requires `flatbuffers` package[cite: 3, 8].
* **Backend (`go.mod`):** Requires Google's FlatBuffers Go package (`github.com/google/flatbuffers/go`)[cite: 4, 10].

### Step 2: Re-introduce Hybrid Input / JSON Upstream Parsers (Optional / As Needed)
If you want to support live template overrides, behavior tuning, and unit grouping (battalion/squad assignment) over WebSockets:
1. **Backend (`backend/internal/game/room.go`):** Expand `SandboxClientInput` struct to parse incoming JSON fields like `TemplateOverride`, `BehaviorOverride`, and `UnitGrouping` inside `HandleWS`[cite: 4, 10].
2. **Frontend Parsers (`src/parsers/jsonParser.ts`):** Implement `serializePlayerAction`, `serializeUnitGrouping`, and `serializeUnitCounts` to ensure upstream commands are correctly serialized before sending over the socket[cite: 5].

### Step 3: Re-add the UI Inspector Tabs & Persistent State Maps
To bring back the interactive tuning panels:
1. **Inspector Components (`src/inspector/`):** Add `StatTuningTab.tsx`, `BehaviorTab.tsx`, and update `Panel.tsx`.
2. **State Lifting (`src/components/PracticeViewport.tsx`):** Lift master dictionary maps (`unitStatsMap`, `unitBehaviorMap`) into parent state variables so they persist across menu toggles and class switches without unmounting.

### Step 4: Regenerate FlatBuffers Code
Run your local FlatBuffers compilation script to populate the `src/generated/` and `backend/internal/generated/` directories so TypeScript and Go recognize the binary data structures.
